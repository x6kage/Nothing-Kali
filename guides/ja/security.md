# セキュリティとオペレーション上の考慮事項

Nothing phoneでNetHunterを使用する際の安全性、法的事項、およびオペレーショナルセキュリティに関する重要なガイダンス。

## 法的免責事項

**明確な書面による許可なしにペネトレーションテストを実施することは、ほとんどの法域で違法である。** NetHunter Pro（Metasploit、aircrack-ng等）が提供するツールは、正当なセキュリティテストと悪意ある攻撃の両方に使用できる。これらのツールの使用方法については、すべてあなた自身の責任となる。

### 合法な場合

- 自分自身のネットワークおよびデバイスのテスト
- 書面によるスコープ合意に基づく許可されたペネトレーションテスト
- 管理されたラボ環境でのセキュリティリサーチ
- CTF（Capture The Flag）競技
- 隔離されたネットワーク上での教育目的の演習

### 違法な場合

- 所有者の許可なくネットワークにアクセスすること
- 自分が所有していない、または許可を得ていないネットワークでパケットをキャプチャすること
- 公共/第三者ネットワークへの認証解除攻撃
- コンピュータシステムへの不正アクセス全般

## デバイス改造後のセキュリティ

### セキュリティ態勢における変化

カスタムカーネルのフラッシュとデバイスのroot化により、セキュリティモデルが変わる：

| 項目 | ストック | 改造後 |
|--------|-------|--------------------|
| ブートローダー | ロック | アンロック（必須） |
| root権限 | なし | フル（Magisk/KernelSU） |
| Verified Boot | 適用 | バイパス |
| OTAアップデート | 自動 | 手動／機能しない |
| SafetyNet/Play Integrity | 合格 | 不合格の可能性 |
| カーネル整合性 | 検証済み | カスタム（未検証） |
| SELinux | Enforcing | Permissiveに設定される場合あり |

### 緩和策

**root権限を管理下に置く：**

- Magisk：銀行/決済アプリにはDenyListを有効化
- KernelSU：許可リストを使用してrootを要求できるアプリを制限
- 信頼できないアプリにrootを付与しない

**デバイスを最新の状態に保つ：**

- カスタムカーネルはOTAを破壊する。Nothing OSをアップデートするには：
  1. ストックカーネルを復元
  2. OTAを適用
  3. カスタムカーネルを再フラッシュ
- [Nothing Archive](https://spike0en.github.io/nothing_archive/docs/firmware)でセキュリティパッチを確認

**fastbootアクセスを保護する：**

- 物理アクセス + fastbootがあれば、誰でもデバイスをフラッシュできる
- ブートローダーモードでデバイスを放置しない
- ペネトレーションテスト時以外はブートローダーの再ロックを検討する（注意：データが消去される）

## オペレーショナルセキュリティ（OpSec）

### WiFiモニタリングの考慮事項

モニターモード使用中、デバイスのWiFi MACアドレスは無線環境上で可視となる。これにより、特定や位置の追跡が可能になる。

**MACアドレスのランダム化：**

```bash
# モニターモードに入る前にMACを変更
ip link set wlan0 down
macchanger -r wlan0       # ランダムMAC
# または
macchanger -m XX:XX:XX:XX:XX:XX wlan0   # 特定のMAC
ip link set wlan0 up
```

> **注意：** `macchanger` はすべてのWiFiドライバで動作するとは限らない。ath12kの場合、インターフェースがダウン状態の時にMACを変更する必要がある。

**無線のフットプリントを最小化する：**

- 実際にテストを行う時のみモニターモードを有効にする
- 完了したらmanagedモードに切り替える
- 使用しない時は外部WiFiアダプタの電源を切る

### USB HID攻撃の考慮事項

USB HID攻撃（DuckyScript、キーボードエミュレーション）は物理的なUSB接続を通じて実行される。以下に注意：

- ターゲットマシンはUSBデバイス接続をログに記録する（Windowsイベントログ、macOS system.log）
- USBデバイスディスクリプタ（VID/PID）でスマートフォンのモデルが特定される
- 一部のエンドポイント保護ソフトウェアは、高速なキーストロークインジェクションを検出する

### ネットワーク攻撃の考慮事項

スマートフォンからMetasploit、Nmap、その他のネットワークツールを使用する場合：

- スマートフォンのIPアドレスはターゲットネットワーク上で可視
- リモートターゲットのテスト時はVPNまたはプロキシを使用する
- ARPおよびルーティングテーブルのエントリにデバイスが表示される
- アグレッシブなスキャンはIDS/IPSアラートをトリガーする可能性がある

## データ保護

### デバイス上の機密データ

NetHunterの使用により機密データが生成される場合がある：

| データの種類 | 場所 | リスク |
|-----------|----------|------|
| キャプチャしたパケット（.pcap） | `/sdcard/` またはchroot | ネットワークトラフィックを含む |
| クラックしたパスワード | chroot／ツール出力 | 認証情報の漏洩 |
| Metasploitセッションログ | chroot内の `~/.msf4/` | 攻撃の詳細 |
| SSHキー | chroot内の `~/.ssh/` | リモートアクセス認証情報 |
| WiFiハンドシェイク | ツール出力ディレクトリ | ネットワークパスワードの露出 |

### テスト後のクリーンアップ

```bash
# キャプチャファイルを安全に削除
su
shred -u /sdcard/capture*.pcap

# Metasploitログの削除
rm -rf /data/local/nhsystem/kali-arm64/root/.msf4/logs/*

# コマンド履歴のクリア
history -c
rm ~/.bash_history ~/.zsh_history 2>/dev/null

# WiFiハンドシェイクの削除
rm -f /data/local/nhsystem/kali-arm64/root/*.cap
rm -f /data/local/nhsystem/kali-arm64/root/*.hccapx
```

### 暗号化

- Androidのフルディスク暗号化を有効にする（Nothing phoneではデフォルトで有効）
- 機密性の高いペンテストデータの保存には暗号化ボリュームを使用：
  ```bash
  # chroot内で暗号化コンテナを作成
  dd if=/dev/urandom of=/root/pentest_data.img bs=1M count=500
  cryptsetup luksFormat /root/pentest_data.img
  cryptsetup open /root/pentest_data.img pentest_data
  mkfs.ext4 /dev/mapper/pentest_data
  mount /dev/mapper/pentest_data /root/pentest/
  ```

## テスト用のネットワーク分離

### 隔離テストネットワークの構築

安全な練習とテストのために：

1. **専用アクセスポイント：** インターネットに接続していない別のWiFiルーターを使用
2. **テストデバイス：** 古いスマートフォン、ノートPC、またはVMをターゲットに
3. **本番ネットワーク禁止：** 実際のユーザー/データが存在するネットワークでは絶対にテストしない
4. **すべてを記録：** レポート用にすべてのテストのログを保持

### リモートテスト用のVPN設定

リモートターゲットをテストする場合（許可がある場合）：

```bash
# chroot内にOpenVPNをインストール
apt install -y openvpn

# VPNに接続
openvpn --config /path/to/client.ovpn

# トラフィックがVPN経由であることを確認
curl ifconfig.me
```

## 責任ある脆弱性開示

テストにより第三者システムの脆弱性が発見された場合（許可を得てテストした場合）：

1. 再現手順とともに**脆弱性を明確に文書化**する
2. 公開前にシステム所有者に**非公開で報告**する
3. 組織に責任ある開示ポリシーがある場合は**それに従う**
4. 公開前に修正のための**合理的な時間を確保**する（90日が標準）

## 緊急事態の対応手順

### デバイスを紛失または盗難された場合

NetHunterがインストールされたroot済みデバイスは、悪意ある者にとって強力なツールとなる：

1. Androidデバイスマネージャー／Google Find My Deviceで**リモートワイプ**
2. デバイスに保存されていた**SSHキーを失効**させる
3. デバイスに認証情報があった**サービスのパスワードを変更**
4. クライアントのペンテストデータがデバイスにあった場合、**関係者に通知**

### 誤って意図しないターゲットを攻撃した場合

1. **即座に停止** — 実行中のすべてのツールを終了
2. 何が起きたかを正確に**記録**（タイムスタンプ、使用ツール、スコープ）
3. 障害を引き起こした場合はネットワーク所有者に**通知**
4. 許可に関して疑問がある場合は**法的助言を求める**
